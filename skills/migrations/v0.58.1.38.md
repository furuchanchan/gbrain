# v0.58.1.38 — loops_close works for federated remote callers

Remote MCP callers holding a multi-source grant were denied on every
`loops_close` call. Two things changed:

- `loops_close` accepts an optional `source_id` (the loop's home source)
  validated against the caller's grant, and when omitted under a
  federated grant it resolves the loop's own source — a close is allowed
  whenever that source sits inside the grant.
- `gbrain loops done|drop <id> --note <text>` records a `closed_by` note
  like the MCP op; CLI closes previously always recorded `manual`.

Also: `loops_mute`/`loops_unmute` now refuse when `source_id` is omitted
and the resolved source holds no Google content — a suppression there
could never match anything.
