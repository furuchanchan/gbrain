# Upgrade to v0.60.32.12: codex SessionStart + UserPromptSubmit context hooks

No migration steps — this release wires two additional codex hook lanes.

- `gbrain bootstrap hooks --harness codex` now manages three events:
  SessionEnd (capture, unchanged) plus SessionStart and UserPromptSubmit
  (ambient recall context, new). The context lanes are synchronous
  `env GBRAIN_HOOK_LANE=harness <bin> hook session-start|user-prompt
  --harness codex` commands — their stdout is the injected context — and
  each gets its own `trusted_hash` entry inside the same managed
  config.toml block, per the same silent-fail trust gate.
- Existing installs keep working but inject no ambient context: re-run
  `gbrain bootstrap hooks --harness codex` to add the two new lanes. The
  writer replaces only its own groups in place and leaves every foreign
  group index (and trust entry) untouched. `gbrain doctor` names an
  install missing the context lanes (`codex_context_hooks_missing`).
- The commands still bake no `GBRAIN_SOURCE`: the context lanes resolve
  the source from the payload cwd's `.gbrain-source` pin at runtime
  (unscoped when no pin or `GBRAIN_SOURCE` applies).
- Codex sessions open on builds without SessionStart/UserPromptSubmit
  support (pre-0.159) simply never fire the new lanes; the `context`
  command's pull path stays the fallback there.

No paid work, no permissions, no schema changes. `gbrain upgrade` applies it.
