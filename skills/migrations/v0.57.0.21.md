# v0.57.0.21 — phantom redirect replays exact fence row assignments

When a phantom page redirects to its canonical page, the fact migration used
to renumber every active phantom row by a `MAX(row_num)` offset. Rows the
disk merge deduplicated were still moved, so the DB numbering diverged from
the canonical fence and the next `extract_facts` reconcile wiped and
re-inserted the page's whole index (churning every fact id).

What changed:

- The disk merge now returns the exact `(phantom row_num → canonical
  row_num, claim)` assignments it wrote, and `migrateFactsToCanonical`
  replays them as per-row compare-and-swap updates.
- A migrated row's `entity_slug` is rewritten only when it still names the
  phantom slug; rows already pointing at a different entity are preserved.
- The migration is idempotent: an identical retry matches nothing and
  reports `migrated: 0`.
- The legacy offset path remains for callers that pass no assignments.

No action required.
