# Upgrade to v0.60.10.4: managed writes stop expiring conversation facts

Any managed write to a page with no `## Facts` fence used to expire every
`row_num`-bearing fact on that page — because the fence reconcile compared
against an empty incoming set. `extract-conversation-facts` writes
`row_num` facts with a `cli:` source on exactly those pages, so one
`add_timeline_entry` or `sources reconcile --apply` pass silently expired a
conversation's whole fact set (20,593 of 20,820 in the report). The reconcile
now only touches fence-owned rows (`COALESCE(source,'') NOT LIKE 'cli:%'` —
the same ownership rule `deleteFactsForPage` uses). No schema migrations and
no new configuration.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.10.4 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Re-extract affected conversations if you hit this.** Facts expired by
   earlier versions keep `expired_at` set — they were not deleted, but recall
   treats them as gone. Re-running
   `gbrain extract-conversation-facts --slug conversations/<x>` re-extracts a
   page's facts. New managed writes no longer expire them.
