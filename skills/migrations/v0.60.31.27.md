# Migration notes — v0.60.31.27

## Harvest failure telemetry carries the refusing gate's code; doctor warns on a structural share

Heartbeat entries with `outcome: 'error'` from the checkpoint/writeback harvest now record `reason: 'operationerror:<code>'` (e.g. `operationerror:writer_lock_unavailable`, `operationerror:idempotency_conflict`) instead of bare `operationerror`. Other exceptions still record the lowered class name (`typeerror`, `error`, ...). Any tooling that matched the literal string `operationerror` should prefix-match `operationerror:`.

`gbrain doctor`'s `memory_writeback` check now exposes `details.backstop_7d.error_reasons` (top-5 reason histogram over 7d) whenever any writeback harvest failed, and reports a warning when failures exceed 20% across at least 10 attempts — a serve that refuses turns before extraction no longer reads green. No migration, schema, or config change is required.
