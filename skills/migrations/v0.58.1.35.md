# v0.58.1.35 — expired-archive purge protects pre-stamp rows; archived failures stay out of doctor

Sources archived before the column-based archive timestamps existed carried
an epoch (1970) expiry, which a bare `gbrain sources purge` read as
"expired" — permanent deletion without the promised 72-hour grace window.
The sweep now skips missing or epoch expiries and reports each one as
blocked with restore + re-archive instructions instead of deleting it.

Doctor's `sync_failures` check no longer counts failures belonging to
archived sources — they cannot be cleared while the source stays archived
(sync refuses them) and carry no live signal. They are surfaced as ignored,
not unresolved.

To reset the 72-hour window on a blocked row, restore it
(`gbrain sources restore <id> --no-federate`) and archive it again.
