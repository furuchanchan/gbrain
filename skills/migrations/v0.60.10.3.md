# Upgrade to v0.60.10.3: dream pattern pages carry the `dream_generated` marker

Pages written by the Dream **patterns** phase were the only dream output that
never carried the `dream_generated` frontmatter marker. Every consumer that
keys on the marker — the transcript-discovery self-consumption guard, search
source-boost demotion, and the extract-atoms/salience `dream_generated`
filters — treated pattern pages as user-authored content. This release stamps
the marker (plus `dream_cycle_date` / `dream_created_cycle_date`) on each
pattern page as the phase publishes it, on both managed and unmanaged publish
paths. No schema migrations and no new configuration.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.10.3 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Nothing else to do.** The next `gbrain dream` patterns phase stamps its
   new pages automatically. Pages written by earlier releases stay unmarked
   until a page update re-runs the stamp — consumers that need the whole
   pattern tree excluded should keep keying on the path as well (the 0.60.5
   transcript-discovery exclusion already does).
