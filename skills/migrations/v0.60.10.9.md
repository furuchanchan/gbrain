# Upgrade to v0.60.10.9: `embedding_query_prefix` for instruction-style embedding models

Brains using asymmetric, instruction-style embedding models — Qwen3-Embedding
(0.6B/4B/8B), e5/BGE, INSTRUCTOR, gte-Qwen — previously sent queries and
documents to the embedding endpoint identically, losing the measured
retrieval quality the model card's query instruction provides (the
reporter's Qwen3-Embedding-0.6B brain went 19→31/40 top-3 hits on
keyword-form questions with the instruction). The new
`embedding_query_prefix` key is prepended inside `embedQuery()` only;
document embedding is unchanged, so **no re-embedding is required**.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.10.9 or newer
   ```

2. **Set the prefix your model card asks for (optional).**

   ```bash
   # Qwen3-Embedding style ($'…' ANSI-C quoting stores a real newline —
   # plain single quotes would write a literal backslash-n):
   gbrain config set embedding_query_prefix $'Instruct: Given a query, retrieve relevant passages\nQuery:'
   # e5 / BGE style:
   gbrain config set embedding_query_prefix 'query: '
   ```

   Env/file planes work too: `GBRAIN_EMBEDDING_QUERY_PREFIX` or
   `embedding_query_prefix` in `~/.gbrain/config.json`. The semantic query
   cache keys on the produced embedding, so rows cached under an old
   prefix simply never match again — no manual invalidation needed.
   Brains on symmetric models (OpenAI, Voyage, Gemini) need nothing.
