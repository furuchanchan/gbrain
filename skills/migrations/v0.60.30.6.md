# v0.60.30.6 — `embed --stale` covers stale take vectors (#5885)

Take claims had vector search and a stale-row contract, but no automatic
writer: `embedStaleTakes` ran only behind the manual `gbrain takes embed`
command, so new and changed takes stayed keyword-only until someone
remembered to run it.

`gbrain embed --stale` now sweeps NULL-embedding takes at the end of a
successfully drained stale pass, inside the same single-flight window.
The cycle's embed phase and the embed minion handlers call the same
`runEmbedCore` stale path, so they cover takes automatically — no new
manual step. Results land on the additive `EmbedResult.takes` field;
`--dry-run` reports `would_embed` without writing, and `--all` keeps its
page/chunk-only meaning.

Doctor reports the new coverage too: `embedding_column_registry` counts
`engine.countStaleTakes()` (active takes whose `takes.embedding` is NULL)
next to chunk coverage and warns with the `gbrain embed --stale` fix hint.

`gbrain takes embed` keeps working as the manual take-only pass.
