# v0.58.1.45 — withdrawal mirror skips metafile-backed pages

A withdrawal-mirror scan used to wedge on a legacy page backed by
`RESOLVER.md` or another sync-skipped metafile (`schema.md`, `index.md`,
`log.md`, `README.md`): the file legitimately diverges from the stored
page — the managed durability block lives only in the file — so the
mirror kept refusing, and the same request's git and embedding follow-ups
were never claimed. Metafile-backed pages now route to the same
no-filesystem-write materialize path as missing or deleted files, so the
scan advances instead of parking.

No schema or data migration; nothing re-imports or re-embeds. No action
needed.
