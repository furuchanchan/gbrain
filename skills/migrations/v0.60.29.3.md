# v0.60.29.3

## v0.32.2 verify dedupes fence rows before counting (#5814)

The v0.32.2 legacy-facts migration's verify step no longer reports false
drift on a page whose `## Facts` fence carries duplicated ACTIVE rows.
The fence-indexing reconcile already deduplicates rows on
`(fact, source)` — the same #1781 rule — so a duplicated fence row
becomes one database row (the rest are marked stale/expired). Verify now
applies that same dedupe before comparing counts, so the migration
completes instead of looping on a permanently "drifted" page.

- Drift detail now names the page and shows both counts, e.g.
  `people/alice (fence=3, db=2)`.
- A fence row whose source is `cli:*` is still counted on the fence
  side; the database count intentionally excludes `cli:*` rows
  (conversation-miner provenance, not fence-derived). That asymmetry is
  unchanged — a genuinely drifted page still fails verify.

No action needed. Brains that stalled mid-migration on this check pick
up at the same phase on the next `gbrain apply-migrations --yes` run.
