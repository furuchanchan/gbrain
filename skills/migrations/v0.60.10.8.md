# Upgrade to v0.60.10.8: extract_atoms wraps transcripts as DATA

`extract_atoms` sent each stored chat transcript to the model as a bare
conversation body. Any transcript page therefore read as a conversation to
continue: instead of emitting the requested JSON array the model replied as
the next assistant turn, and the page counted as a `malformed model output`
failure on every run (3/3 on both Haiku and Sonnet in the reporter's corpus)
until it tombstoned. The extraction prompt now wraps the body in
`<transcript>` tags and states that the content is DATA to analyze — not a
conversation to continue — so the model emits atoms instead of the next
turn. No schema migrations and no new configuration.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.10.8 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Re-extract pages that tombstoned as malformed.**

   ```bash
   gbrain extract-atoms --source <source>     # re-runs skipped pages
   ```

   Tombstoned pages from earlier runs re-extract normally — the wrapped
   prompt is the only change; `locateQuote` quote provenance is identical
   because the body inside the wrapper is byte-for-byte the same cut.
