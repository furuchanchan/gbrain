# v0.58.1.36 — large PGLite brains no longer freeze mid-import

On a brain much larger than `shared_buffers`, `gbrain sync` / `gbrain embed`
could freeze at 100% CPU after roughly every 2,000 imported pages: the
in-process Postgres ran an automatic checkpoint inside a buffer flush and
waited for I/O that only it could finish. The engine now issues an explicit
top-level `CHECKPOINT` once WAL distance passes 256 MB
(`GBRAIN_PG_CHECKPOINT_MB`, non-positive disables), well before the automatic
trigger can fire mid-flush.

Large brains also benefit from faster resumes: WAL replay on startup shrinks
because checkpoints now complete instead of deadlocking. No action required.
