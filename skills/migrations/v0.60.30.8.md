# v0.60.30.8 — harness token rotation preserves takes_holders (#5893)

Re-running `gbrain bootstrap harness` rotates every harness token: mint a
fresh token, wire it, verify, then revoke the old one. The fresh mint
carried `allowed_operations` and the `source_id` federation grant forward
but always seeded `takes_holders` with the default `['world']`. An
operator who had widened the list — `gbrain auth permissions
bootstrap-harness-<host> set-takes-holders garry,team` — found every
connected harness silently back to world-only takes after the next
rotation, with no warning.

The mint step now reads the rotating-out token's `permissions.takes_holders`
(by token id, the same row the [C7] mint-first rotation already tracks)
and seeds the new token with that list. Tokens still on the default keep
the default; a missing or damaged permissions object falls back to
`['world']` exactly as before. If a token was created but never rotated,
nothing changes — this only affects re-runs of `bootstrap harness`.

Operators relying on rotation to RESET holders to `['world']` should run
`gbrain auth permissions <name> set-takes-holders world` after the re-run,
or revoke and mint a fresh token instead.
