# Upgrade to v0.60.52.1: `--cleanup-dead-local-locks` applies to shared-skills activation

`gbrain sources writer activate --shared-skills --cleanup-dead-local-locks` now
honors the flag it already accepted: the shared-skills activation path applies
the same legacy-writer-lock rule as base activation. A `gbrain_cycle_locks`
row held by a provably dead process on this host is removed inside the
activation transaction and activation proceeds; live, young or foreign holders
still refuse with `writer_not_quiesced`. Without the flag every lock row
refuses, exactly as before.

1. **Finish the upgrade.** `gbrain upgrade` runs it. To be sure, on the brain
   host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   No schema migration ships with this release.

2. **If shared-skills activation is wedged on a dead lock.** Preview what the
   cleanup would remove — it changes nothing:
   ```bash
   gbrain sources writer activate --shared-skills --confirm-quiesced \
     --cleanup-dead-local-locks --dry-run --json
   ```
   `legacy_locks` lists each inspected row with its liveness classification.
   Then activate:
   ```bash
   gbrain sources writer activate --shared-skills --confirm-quiesced \
     --cleanup-dead-local-locks
   ```
   Only same-host holders whose PID is provably dead past the grace window are
   eligible; a lock owned by a living process or another host still refuses.
