# Upgrade to v0.59.18.3: providers env shows resolved base URLs and DB-plane overrides

This release changes `gbrain providers env` output only: it adds the resolved
base URL with provenance and consults DB-plane `provider_base_urls.*` values
for openai-compat recipes. It does not change how requests are routed, does not
authorize new provider spend, and installs no new background services.

1. **Prepare a maintenance window.** Stop old CLI, resident, sync and worker
   processes for this brain. Take and verify an engine-appropriate full backup.
   Mixed old/new writers are not a supported upgrade procedure.

2. **Upgrade and confirm.** Run `gbrain upgrade --no-autopilot-install`, then
   confirm `gbrain --version` reports v0.59.18.3 or newer. If the binary
   upgraded but schema work did not complete, apply
   `gbrain apply-migrations --yes --no-autopilot-install` after the backup and
   quiescence checks.

3. **Verify provider resolution.** Run `gbrain providers env <id>`. The
   `Base URL:` line now names the value and the plane it came from — file
   plane, DB plane (when a brain is reachable and the recipe is
   openai-compat), env var, or recipe default — plus a `Resolution scope:`
   line describing exactly which planes were consulted. Native providers
   still never read the DB plane.

4. **Check overrides after upgrade.** A `provider_base_urls.<id>` value set
   via `gbrain config set` applies to openai-compat providers and now shows
   as `(db plane)` in `providers env`. If a configured URL is malformed, the
   command prints `(invalid URL — value redacted)` rather than its contents;
   fix the stored value with `gbrain config set`.

If a step fails, preserve the backup and diagnostic output and follow the
linked recovery guide. Do not run a destructive reset or expand a spending
authorization to make the status turn green.
