# Upgrade to v0.59.18.1: managed connector checkpoints key on stable configuration

This release changes how managed connector checkpoint keys are computed:
cycle bookkeeping (`last_source_cycle_at`, `last_full_cycle_at`) is excluded
from the hashed configuration. It adds no new background services, installs
no connectors, and authorizes no external calls beyond the syncs the operator
already scheduled.

1. **Prepare a maintenance window.** Stop old CLI, resident, sync and worker
   processes for this brain. Take and verify an engine-appropriate full
   backup. Mixed old/new writers are not a supported upgrade procedure.

2. **Upgrade and confirm.** Run `gbrain upgrade --no-autopilot-install`,
   then confirm `gbrain --version` reports v0.59.18.1 or newer. If the binary
   upgraded but schema work did not complete, apply
   `gbrain apply-migrations --yes --no-autopilot-install` after the backup
   and quiescence checks.

3. **Let the next managed sync run.** A Gmail or GitHub backfill that was
   interrupted by a checkpoint-key change resumes under the stable key.
   Checkpoints written under the immediately preceding full-config digest
   are adopted automatically when equivalence is provable.

4. **Expect one fresh backfill for older orphaned rows.** Checkpoint rows
   orphaned under bookkeeping states older than the previous config cannot
   be re-keyed (their fingerprint preimage is opaque). For those rows the
   next sync performs one fail-closed historical backfill, after which the
   checkpoint identity stays stable across cycle bookkeeping stamps.

5. **Verify.** Watch the next managed sweep for a resumed generation rather
   than a restart from generation 0; `gbrain doctor` reports connector
   checkpoint state for managed sources.

If a step fails, preserve the backup and diagnostic output and follow the
linked recovery guide. Do not run a destructive reset or force a revision
to make the status turn green.
