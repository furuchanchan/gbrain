# Migrating to v0.60.28.9

## What changed

`extract links --by-mention` no longer produces word-internal or
cross-word matches for Hangul-only entity names (#5829): a match is
accepted only when the matched span equals the entry text (modulo
whitespace runs) and the character before it is not a Hangul syllable.
Han and Kana entries are unchanged.

## If you relied on the old matches

- A Hangul entity name that is also a common noun or connective (e.g.
  "지원" = support, "인하여" = due to) can still match as a standalone
  word — the boundary rule cannot fix that. Exclude the entity entirely:
  `gbrain config set by_mention.exclude_slugs '["people/jiwon"]'`
  (or a comma-separated list). The exclusion applies to every
  `buildGazetteer` consumer: the scan, `stale_mentions`, extract-ner and
  timeline-from-meetings.
- Existing links produced by word-internal matches are now flagged by
  the `stale_mentions` doctor check (correctly — they no longer follow
  from the gazetteer). Reconcile with
  `extract links --by-mention --rebuild`.
- Names typed with a space in the body ("삼성 카드" for entity
  "삼성카드") no longer link — the documented trade-off of the
  literal-span rule.
