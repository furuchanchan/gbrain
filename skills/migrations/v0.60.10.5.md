# Upgrade to v0.60.10.5: stuck write receipts from provider outages can settle

A write receipt whose embedding effect failed can now be resolved after its
page moved on. Previously `gbrain sources writer retry-effects` refused every
superseded obligation with `revision_conflict`, and receipt compaction skips
any receipt with a non-committed effect — so an embedding-provider outage
left permanent receipt reservations that nothing could clear. The retry now
settles the effect as `committed` when the obligation is vacuous (page
deleted) or when the current revision's vectors are already complete, and it
still refuses when newer content has unembedded chunks. No schema migrations
and no new configuration.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.10.5 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Clear stuck receipts if you hit this.**

   ```bash
   gbrain sources writer retry-effects <source> --request-id <id> --dry-run
   gbrain sources writer retry-effects <source> --request-id <id>
   ```

   `--dry-run` reports `would_supersede` for settle-able receipts. If a
   receipt still refuses, its current revision was never embedded — run
   `gbrain embed --stale` first, then retry. Settled receipts compact on the
   normal `persistence.receipt_retention_days` schedule.
