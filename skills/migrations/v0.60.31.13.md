# Migration notes — vv0.60.31.13

## Ambient writeback dedups against recent agent saves

With `memory.auto_writeback` enabled, a Stop-hook harvest re-extracted the
last user turn ~30–70 s after the agent saved the same statement with
`remember`. When the phrasings differed, or the agent filed the fact on a
different entity, both rows stayed active — the per-entity dedup never
compared across entities — and the hot-memory block injected every stored
copy side by side.

### What this release changes

- **Writeback lane (`hook:writeback` only)**: extracted facts now dedup
  against active facts written inside a 10-minute window regardless of
  entity — normalized-text equality, or cosine ≥ 0.95 for cross-session
  rows and ≥ 0.88 for same-session rows (the window + session bound keeps
  the looser bar from folding unrelated claims). Matched rows count as
  `duplicate` with the existing fact id, on both managed and unmanaged
  brains. Other lanes (sync, `put_page`, `extract_facts`, compact) are
  byte-identical.
- **Hot memory (`_meta.brain_hot_memory`)**: injection rows collapse
  near-duplicate phrasings — normalized-text equality or cosine ≥ 0.85
  when both rows carry a same-model embedding — keeping the most confident
  phrasing. Collapse only hides a row for this injection; nothing is
  deleted or superseded.

### Recovery

Existing duplicate rows are not rewritten. Run `gbrain facts relink` /
`gbrain repair` flows as before to consolidate drift; new writeback
extractions stop producing the second copy immediately.
