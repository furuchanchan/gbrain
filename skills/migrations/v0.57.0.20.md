# v0.57.0.20 — fence reconcile no longer churns fact ids

The unmanaged `extract_facts` cycle reconciles a page's `## Facts` fence to
the `facts` table by fence coordinate (`row_num`) instead of the claim/source
pair.

What changed for existing brains:

- **Stable fact ids.** Editing or removing one fence row deletes and
  re-inserts only the changed/departed rows (inside the insert transaction,
  `deleteForPageFirst.onlyIds`). Rows that did not change keep their ids, so
  supersession targets, `forget_fact` receipts, and external references stay
  valid across reconciles.
- **No content-key collapse.** Two fence rows sharing a claim and source but
  carrying different validity windows index as distinct facts. There is no
  dedupe step anymore; every fence row maps to its own DB row.
- **Supersession follows replacements.** When a supersession target is
  re-inserted with a new id, the struck row re-inserts too and its
  `superseded_by` re-resolves onto the fresh row (fixpoint over chains).
- **Delete-only reconcile.** A reconcile that removes rows without inserting
  any still runs the scoped delete in one transaction.

No action required; the change takes effect on the next `extract_facts` run.
