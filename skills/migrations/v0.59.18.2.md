# Upgrade to 0.59.18.2: single-runner apply-migrations on Postgres

This release adds a Postgres single-runner lock to `gbrain apply-migrations`
and distinguishes "swap failed" from "postinstall still running" in
`gbrain upgrade` on bun-link installs. No schema change and no data migration;
it does not authorize paid repair or new background services.

1. **Upgrade normally.** Run `gbrain upgrade`, then confirm
   `gbrain --version` reports 0.59.18.2 or newer.

2. **Check before re-running migrations.** If an earlier upgrade reported
   `bun install` did not finish, the migration child may still be running in
   the background. On Postgres brains, `gbrain apply-migrations --list` now
   reports the in-flight run (holder pid, host, and when the lock lapses);
   `pgrep -fl apply-migrations` finds a detached local child. Wait for it to
   finish — a second runner now refuses instead of writing duplicate
   backfills in parallel.

3. **Recover only when nothing is in flight.** If the binary upgraded but its
   schema work did not complete and no run is in flight, use
   `gbrain apply-migrations --yes --no-autopilot-install`. The lock releases
   itself when the holding run ends or its TTL lapses; do not force it while
   the holder is alive.

Do not run a destructive reset or expand a spending authorization to make the
status turn green.
