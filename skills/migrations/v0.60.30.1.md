# v0.60.30.1

## takes_supersede keeps the supersession chain on managed brains (#5886)

`gbrain takes supersede` (and the `takes_supersede` mutation) now stamps
`superseded by #N` into the struck row's source cell — the documented
fence shape — instead of writing a self-referential pointer into the new
row's source. The new row keeps the caller's own source.

On a managed brain, the canonical publication derives `takes.superseded_by`
only from an inactive row's `source` cell, so the old shape meant the
pointer never reached the database — and every later re-publication of
the page re-projected NULL over it.

- Existing superseded rows are not rewritten; the fix applies to new
  supersedes. A page whose struck row already shows `superseded by #N`
  in its fence projects correctly as before.
- Unmanaged brains behaved correctly for the database column (the mirror
  passed the pointer explicitly) but the fence itself was inconsistent —
  the markdown now matches the documented shape there too.

No action needed.
