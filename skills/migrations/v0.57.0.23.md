# Upgrade to v0.57.0.23: list output escapes control characters; lint --fix no longer fabricates `created`

Preserve the agent's identity, capture choices, provider choices and source
grants. This release changes only display output and lint behaviour; it
does not change what is stored, indexed, or who can read pages.

## Upgrade the installation

1. For a managed brain, identify and gracefully stop/drain its owner and
   older workers on every host using the deployment's normal shutdown
   procedure. Keep a verified full database backup and the original
   installation. A Git remote alone is not a full backup.
2. Upgrade through the installation's supported path:

   ```bash
   gbrain upgrade --no-autopilot-install
   ```

3. Restart the upgraded owners/workers and verify `gbrain --version` and
   `gbrain sources writer status --json`.

## What changes for callers

- `gbrain list` rows escape `\\`, tab, CR, and LF inside each cell. Parsers
  that previously consumed raw titles should unescape `\\t`, `\\r`, `\\n`,
  and `\\\\` (backslash first when decoding). Titles without control
  characters are printed identically to before.
- `gbrain lint` no longer reports `missing-created` on pages that carry
  `event_date`, `date`, `published`, `captured_at`, or `ingested_at`, and
  `lint --fix` no longer inserts a `created` field. Files previously
  "healed" this way keep the field harmlessly; nothing is removed.
