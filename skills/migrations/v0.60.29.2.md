# v0.60.29.2

## Stop-hook write-back skips gbrain's own claude-cli sessions (#5820)

gbrain's ambient write-back Stop-hook backstop banked the last user turn of
EVERY Claude Code session — including gbrain's own `claude --print`
extraction subprocesses, which run under the user's hooks. The reporter
measured 618 banked `.wb-` files in 6 hours and a permanent `self_capture`
doctor warning.

The Stop lane now applies the same self-transcript guard the SessionEnd
lane added in #5413: the claude-cli scratch-cwd fingerprint in the
transcript path or the payload cwd skips banking before the transcript is
even parsed (typed `self_transcript` reason, classified by-design `ok` in
the `writeback-bank` heartbeat). The serve-side harvest gained the sweep's
`self_capture` classification too — a banked turn whose session id is a
known claude-cli self session gets a terminal `.ingested` sidecar instead
of an extraction call.

No action needed. Banked `.wb-` files from before this fix that still sit
un-ingested are classified `self_capture` and skipped by both the sweep and
the harvest on their next pass.
