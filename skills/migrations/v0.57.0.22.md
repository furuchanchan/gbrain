# v0.57.0.22 — v0.32.2 backfill: per-file snapshot refusal + atomic file/DB write

The `fence_facts` migration phase (v0.32.2) had two correctness defects:

- It refused to run when the target source's checkout had *any*
  uncommitted file — including files the backfill never touches. The
  refusal is now per target file: a page is only rewritten while its
  on-disk bytes match the page's DB snapshot (compiled_truth, timeline,
  frontmatter). Uncommitted edits to the target itself still refuse,
  since they always diverge from the snapshot.
- The per-row `row_num` UPDATEs ran autocommitted after the file rename,
  and `pages.compiled_truth` was never refreshed — a crash left a fence
  on disk the DB did not own plus a stale page body. The row stamps and
  `refreshPageBody` now run in one transaction under the page lock, and
  the renamed file is rolled back if the DB write fails.

No action required.
