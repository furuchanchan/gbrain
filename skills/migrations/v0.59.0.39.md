# v0.59.0.39 — `gbrain recall --grep` filters in SQL before the LIMIT on the local path

On a local (non-thin-client) install, `gbrain recall --grep TEXT` fetched the
newest `--limit` facts first and applied the text filter afterwards. Any match
older than that window reported `No matching facts.` even though the fact was
stored and active — and since `--limit` caps at 100, older matches were
unreachable.

`--grep` now narrows in SQL before the LIMIT on every local recall arm
(entity, session, `--since`, and the default listing), the same behavior the
MCP op and thin-client paths already had. If you scripted around this with a
large `--limit`, you can drop the workaround.

`--supersessions` still filters client-side: its audit-log list call takes no
grep option, so behavior there is unchanged.
