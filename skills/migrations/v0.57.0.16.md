# v0.57.0.16 — queue lane writes a facts:absorb:complete receipt

The in-process `facts:absorb` queue lane used to discard the pipeline
result, so a completed extraction was indistinguishable from a silent
skip — absorb health checks and failure triage could not tell success
from a swallowed run.

What changed:

- A clean (non-aborted, non-skipped) finish now logs an ingest row under
  a sibling source type `facts:absorb:complete` carrying the page body
  hash, model, inserted/duplicate/superseded counts, and fact ids.
- The sibling source type keeps `facts_extraction_health` — which groups
  `facts:absorb` rows as failure reasons — from counting successes as
  failures.
- Aborted runs and extractor-skip outcomes keep their existing
  accounting (or deliberately none). A logging failure only warns and
  never aborts the run.

No action required.
