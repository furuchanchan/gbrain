# v0.54.6.0

- `revision_conflict` write receipts now surface the typed reason — a missing `expected_revision` reports `The page already exists; an expected revision is required.` (a usage fix) rather than `The page changed` (a data race) — and the durable `outcome` records `expected_revision`/`current_revision` (#5293). The precondition itself is unchanged: read the revision first, pass `--expected-revision`. No action needed.
