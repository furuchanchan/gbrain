# Migration notes — v0.60.31.12

## Shared-skills enrollment epoch refresh

For each `gbrain bootstrap harness` (or `agent-install --harness`) shared-skills
enrollment whose server-side epoch was superseded by a later re-enrollment
(same principal joining again over MCP), previous releases left the recorded
epoch stale forever: every `sync_brain_skills` and `leave_brain` was refused
`membership_inactive`, a harness re-apply could never finish leaving the old
enrollment, and `gbrain bootstrap harness --status` showed nothing wrong.

### What this release changes

- **Repair command**: `gbrain bootstrap harness --refresh-skills` re-joins each
  recorded live enrollment under its recorded credentials; the adapter receipt
  and the router adopt the server's current epoch. No tokens are minted and no
  agent-target wiring changes.
- **Status**: `--status` probes each live enrollment (`sync_brain_skills` with
  the recorded epoch — refused stale epochs issue no batch). Text output marks
  a superseded epoch `STALE` with the repair command; `--json` adds
  `enrollment_epoch`, `enrollment_stale`, `enrollment_server_epoch`.
- **Leave**: the adapter treats `membership_inactive` from `leave_brain` as
  already-completed remote cleanup (`remote_membership_reason: superseded`),
  so a re-apply converges instead of retrying a refusal forever.

### Recovery

```bash
gbrain bootstrap harness --status          # shows STALE on a superseded epoch
gbrain bootstrap harness --refresh-skills  # adopt the server's current epoch
```

No schema changes; no manual steps for installations whose epoch is current.
