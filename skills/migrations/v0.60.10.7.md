# Upgrade to v0.60.10.7: v0.28.0 takes backfill no longer wedges on managed brains

On a managed brain the v0.28.0 migration's backfill phase was refused
`writer_coordinator_required` — `extractTakesFromDb` wrote the `takes` table
outside the persistence coordinator, tripping the `managed_writer_guard`
trigger. v0.28.0 recorded `partial` every run until it wedged, which left
every later orchestrator migration (`0.29.1`, `0.31.0`, `0.32.2`, `0.43.0`,
`0.46.3`) stuck `pending`. The backfill now runs inside the coordinator
capability scoped to the enumerated sources, so the phase completes and the
chain proceeds. No schema migrations and no new configuration.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.10.7 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Unwedge v0.28.0 if yours is stuck.**

   ```bash
   gbrain apply-migrations --list          # look for "wedged 0.28.0"
   gbrain apply-migrations --force-retry 0.28.0
   gbrain apply-migrations --yes --no-autopilot-install
   ```

   The backfill phase now completes (pre-managed pages' fenced takes index
   normally), and the pending orchestrator migrations continue on the next
   run.
