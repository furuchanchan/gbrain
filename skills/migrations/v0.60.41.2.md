# Upgrade to v0.60.41.2

A sync-robustness fix: managed sync quarantines files whose frontmatter cannot
be parsed instead of blocking the whole source behind them. Nothing needs
your agreement; nothing new is sent anywhere.

1. **Finish the migration.** `gbrain upgrade` runs it. To be sure, run on the
   brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   No schema migration ships in this release. Restart every `gbrain serve`,
   autopilot and worker so the quarantine screen is live.

2. **Resume a blocked catch-up.** If a sync was `BLOCKED` behind a
   `YAML_PARSE` file, fix nothing first — just rerun it:
   ```bash
   gbrain sync --source <id> --no-pull --retry-failed
   ```
   The broken file is recorded in the failures ledger as
   `invalid_frontmatter` / `quarantined` (see `gbrain doctor` and
   `gbrain sources status <id>`), the cursor advances, and the rest of the
   manifest imports. The run reports `quarantined_files` /
   `quarantined_paths`.

3. **Let a repaired file import by itself.** Fixing the file's frontmatter
   and committing changes its blob hash, which produces a new manifest
   entry — the next `gbrain sync` imports it normally. No manual retry flag
   is needed.
