# Migration notes — v0.60.31.34

## `writer activate` reports `reason: 'already_enabled'` on the idempotent no-op

Re-running `gbrain sources writer activate --confirm-quiesced` on a brain whose managed persistence is already enabled returns `{enabled: true, activated: false}` as before, now with two new fields: `reason: 'already_enabled'` and `next_action` (points at `gbrain sources writer status --json` for the ingress/consumer and worktree heartbeat state that activation does not own). Every real activation failure still throws a named refusal, so automation that treated `activated:false` as ambiguous can now distinguish "already done" from "failed" without parsing error text. No migration, schema, or config change is required.
