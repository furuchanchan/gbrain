# Upgrade to v0.56.1.18: backup restore flushes restored files with write access on Windows

Preserve the agent's identity, capture choices, provider choices and source
grants. This release fixes a Windows-only restore crash; it does not change
what is backed up, where archives are written, or who can run a restore.

## Upgrade the installation

1. For a managed brain, identify and gracefully stop/drain its owner and
   older workers on every host using the deployment's normal shutdown
   procedure. Keep a verified full database backup and the original
   installation. A Git remote alone is not a full backup.
2. Upgrade through the installation's supported path:

   ```bash
   gbrain upgrade --no-autopilot-install
   ```

3. Restart the upgraded owners/workers and verify `gbrain --version` and
   `gbrain sources writer status --json`.

## If a restore already failed on Windows

The failed run left the reserved destination root in place with an
incomplete receipt. Remove that root and re-run the same
`gbrain backup restore <archive> --into <new-absent-root>`; archives written
by older versions remain valid.
