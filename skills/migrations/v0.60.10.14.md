# Upgrade to v0.60.10.14: migration budget settles overage to actuals

This release completes the migration-budget settle begun in v0.60.10.12: a
request whose measured usage exceeds its conservative ceiling now debits the
real spend, and a settle that pushes cumulative actuals past
`--max-cost-usd` commits the debit before signaling exhaustion. No schema
changes, no new services, no external calls beyond the migrations the
operator already authorized.

1. **Prepare a maintenance window.** Stop old CLI, resident, sync and worker
   processes for this brain. Take and verify an engine-appropriate full
   backup. Mixed old/new writers are not a supported upgrade procedure.

2. **Upgrade and confirm.** Run `gbrain upgrade --no-autopilot-install`,
   then confirm `gbrain --version` reports v0.60.10.14 or newer. If the
   binary upgraded but schema work did not complete, apply
   `gbrain apply-migrations --yes --no-autopilot-install` after the backup
   and quiescence checks.

3. **Resume a capped migration.** A run that stopped because debited
   authorization reached the cap was accounting at ceiling estimates; resume
   with `gbrain migrate embeddings --max-cost-usd <cap>` — debits now
   track measured usage in both directions, so under-runs release
   authorization and over-runs count the real spend.

4. **Expect honest exhaustion.** If a settle pushes cumulative actuals over
   the cap, the run stops with `BUDGET_EXHAUSTED` after the real debit is
   committed — inspect `gbrain migrate embeddings --status`, then resume with a
   higher explicit cap if intended.

5. **Verify.** `debited_usd` in the migration state now equals the sum of
   measured usage for settled attempts plus ceiling estimates for
   unsettled/ambiguous ones; it can exceed a stale ceiling's arithmetic but
   never under-counts a spent request.

If a step fails, preserve the backup and diagnostic output and follow the
linked recovery guide.
