# 0.60.10.11 — Atom retry supersede (#5699)

A malformed atom batch that wedged after a revision-only source change now has a
supported recovery path — no SQL checkpoint edits or private patches needed.

If a retry refuses with `The original atom input changed; this retry cannot reuse
it.` while the page's `content_hash` is unchanged (only `knowledge_revision`
moved), rerun the suggested job with the supersede flag:

```bash
gbrain jobs submit extract-atoms-drain \
  --params '{"sourceId":"<source>","retryRequestId":"<request_id>","supersede":true}' \
  --max-attempts 1 --follow
```

The retry re-anchors on the current source snapshot and runs the normal
authority/revision checks. It still refuses when the source content actually
changed — in that case the drain already treats the input as a new batch.
Historical receipts are kept.
