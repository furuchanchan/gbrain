# Upgrade to v0.54.37.0: single-source large-sync backfill restored

Preserve the agent's identity, capture choices, provider choices and source
grants. This release repairs a silent data-freshness gap; it does not change
any cost gate — the deferral still happens, it is just actually followed up
now.

## Upgrade the installation

1. For a managed brain, identify and gracefully stop/drain its owner and older
   workers on every host using the deployment's normal shutdown procedure.
   Keep a verified full database backup and the original installation. A Git
   remote alone is not a full backup. Do not mix old consumers with the new
   durable intent types.
2. Upgrade through the installation's supported path. Preserve independent
   opt-outs where applicable:

   ```bash
   GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
   ```

   Do not add credentials, enable capture, install services or start a paid
   backfill as an upgrade side effect. If a migration reports a failed phase,
   inspect it; a partial result is not completion.

## What changed

- A single-source sync whose diff exceeds 100 files now delivers its
  embedding deferral on worker-backed engines too: the embed-backfill job is
  submitted (or the manual `gbrain embed --stale --source <id>` command is
  printed when no worker exists), matching `sync --all` semantics —
  intrinsic delivery is still gated on `sync.federated_v2` for worker-backed
  engines.
- If you previously saw "deferring embeddings" with no follow-up job, run
  `gbrain embed --stale` once to clear any stranded chunks; new large syncs
  no longer strand them.
