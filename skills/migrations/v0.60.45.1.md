# Upgrade to v0.60.45.1

A robustness fix: one repair kind whose preview cannot run no longer takes
`gbrain doctor --remediation-plan` (or `--remediate`) down — the step is
listed with its failure reason and the rest of the plan still prints.
Nothing needs your agreement; nothing new is sent anywhere.

1. **Finish the migration.** `gbrain upgrade` runs it. To be sure, run on the
   brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   No schema migration ships in this release. Restart every `gbrain serve`,
   autopilot and worker so the per-kind preview is live.

2. **If a repair preview was blocking the plan.** Rerun the plan:
   ```bash
   gbrain doctor --remediation-plan
   ```
   The unplannable kind now shows as `R<n>. <kind> — preview failed:
   <reason>` with the manual preview command (`gbrain repair <kind>`), and
   every other step still prints. In a `--remediate` run that step reports
   `failed` with the recorded reason; the remaining steps run.

3. **Work the failed kind by hand when needed.** A preview failure means the
   kind could not size its work on this brain (for example a statement
   timeout over a large journal) — `gbrain repair <kind>` may still succeed
   interactively, and fixing the underlying cause (indexes, retry) restores
   its plan entry on the next run.
