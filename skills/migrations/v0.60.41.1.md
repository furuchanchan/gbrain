# Upgrade to v0.60.41.1

A repair-only fix: `gbrain repair failed-writes` can now replay writes that
arrived through a subagent or another delegated namespace, and the apply prints
why each still-refused item stayed refused. Nothing new needs your agreement;
the repairs below are free.

1. **Finish the migration.** `gbrain upgrade` runs it. To be sure, run on the
   brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   No schema migration ships in this release. Restart every `gbrain serve`,
   autopilot and worker so the corrected fence is live.

2. **Replay the restricted-namespace receipts.** If an earlier `repair
   failed-writes` apply left subagent or trusted-workspace writes refused with
   `put_page via subagent requires ctx.subagentId`, the receipts are still
   stored. Preview and apply again:
   ```bash
   gbrain repair failed-writes --source <id>
   gbrain repair failed-writes --source <id> --apply --expect <preview-hash>
   ```
   A replay still does no more than the original caller could: the stored
   receipt's delegated namespace is verified first, and an item whose stored
   authority no longer covers its slug is reported `authority_revoked` with
   the reason printed.
