# Upgrade to v0.54.38.0: managed Windows sync restored

Preserve the agent's identity, capture choices, provider choices and source
grants. This release repairs a sync path that could silently plan deletes;
it does not weaken any write coordination — managed deletes still require
the prepared intent and the writer contract.

## Upgrade the installation

1. For a managed brain, identify and gracefully stop/drain its owner and older
   workers on every host using the deployment's normal shutdown procedure.
   Keep a verified full database backup and the original installation. A Git
   remote alone is not a full backup. Do not mix old consumers with the new
   durable intent types.
2. Upgrade through the installation's supported path. Preserve independent
   opt-outs where applicable:

   ```bash
   GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
   ```

   Do not add credentials, enable capture, install services or start a paid
   backfill as an upgrade side effect. If a migration reports a failed phase,
   inspect it; a partial result is not completion.

## What changed

- Managed sync comparisons of `pages.source_path` now normalise Windows
  separators on Windows, matching the reconcile audit. Incremental sync no
  longer throws `page_identity_changed` for pages whose stored path uses
  backslashes, and `sync --full` no longer plans deletes for them.
- The stored value is healed automatically: the sync's `IS DISTINCT FROM`
  rewrite stores the canonical forward-slash form on the next successful
  run, so no data migration is required.
- If you previously avoided `sync --full` for this reason, it is now safe;
  a `sync --dry-run` shows the plan before any write.
